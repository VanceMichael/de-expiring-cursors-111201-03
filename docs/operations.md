# 本地运行说明

先运行单元测试，再执行演示命令。演示从干净临时目录发起真实请求并处理响应，不需要外部站点。
常规导入失败时返回非零退出码，事务中的原文和记录会一起回滚，可保留源文件再次处理。
查询模式只读取当前数据库，不会补采或删除来源数据。需要长期保留证据时，请备份整个数据库。
本地响应服务支持状态码、响应头、文本或 base64 字节正文；未配置路径返回未找到。
每条路径的脚本独立推进，最后一个响应会重复；可借请求记录核对调用顺序。
数据文件的路径均相对项目根目录，修改工作目录前请确认输入和数据库参数。

## 扫描完整性约定

行数对不上不能作为完整性判断依据：目录新增、翻页期间的修订与漏采都会改变行数。
请以扫描报告为准：`coverage` 给出叶子分片拼满扫描区间的覆盖证明，
`incomplete` 列出未完成区间，`watermark` 是可靠水位——其前方所有区间完整时才前移，
水位与扫描起点之间存在未核实空洞时不得前移。

- 只有有效终页证据（next 为空）且窗口未截断才能封窗；短暂空页不等于结束，
  游标未推进会立即停止以防死循环。
- 游标失效后只重扫当前分片窗口；反复失效超过上限的分片挂起，不会无限重试。
- 窗口截断时按时间二分细分；到最小时间粒度仍超上限的分片挂起（suspended），
  不自称完整，也不会无限自分裂。挂起分片会随后续扫描（起点按约定回看范围回退）
  自动重采，供应商上限放宽后即可封窗。
- 退出码：0 表示扫描计划内全部分片完整封窗；3 表示扫描结束但存在挂起分片，
  结果不完整；1 表示异常中断，数据库保留现场，可用同一命令续跑。
- 半开窗口无长事务快照，翻页期间的插入可能落在已翻过的位置；约定回看范围内的
  新到数据由后续扫描补采，重复返回按供应商主键与修订号消化，旧修订不盖新值。
- 每页原文与导入凭据同事务入库，可按记录追溯来源分片（provenance）。
